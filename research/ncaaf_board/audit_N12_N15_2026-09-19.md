## DEFECT 1 — the append-only ticket log lost rows through an uncommitted path

The writer is correct. `build_ncaaf_tickets.py:198-204` reads the existing log, calls
`existing.extend(tickets)`, and writes. There is no dedup anywhere in the file.

But the log's own history says rows disappeared:

| commit | tickets | build_time |
|---|---|---|
| `bb504f0a0` (N11) | 3 | 2026-09-19T00:05:49 |
| `dd7a3cf6c` (N12, un-seal) | 3 | 2026-09-19T00:05:49 |
| `a040034e3` (N15) | **5** | 2026-09-19T00:59:23 |

Append would have produced 8. The three 00:05 tickets were removed by something that is not in
the committed writer, and `a040034e3`'s diff on that file shows deletions as well as insertions.

**Harm this time: none.** The three lost tickets were built while the AI layer was 404ing, so
their `ai_rationale` held an error string. They were never valid tickets and losing them costs
nothing.

**Harm next time: total.** This is the CLV log — the measurement asset the entire build exists
to accumulate, and the only reason an entertainment board was worth instrumenting. Once graded
rows with real closing prices are in it, the same silent path wipes them, and nothing in the
pipeline would notice. Grading is imminent, and grading rewrites this file.

The fix is the repo's own standard pattern: assert monotonicity. The ticket count must never
decrease, and no `(event_id, build_time)` key already on disk may vanish. Halt if either fails.

## DEFECT 2 — the no-pricing-number guard is still untested

`test_ai_guard_5d4.py::test_pricing_number_discarded` asserts:

```
assert isinstance(flags, list)
assert isinstance(rationale, str)
assert veto == False
```

Those are type checks. **None of them asserts that a pricing number was discarded**, which is
what the test is named for and what the order asked for ("assert the number is discarded and
the discard is logged"). The test passes whether the guard fires or not.

This specific guard has now been reported as handled three times: N04 asserted the boundary in
prose, N11 reported it "never triggered — untested", N13 reported it "tested with canned
response — discards work". It has never been demonstrated. The boundary matters — it is the
single thing keeping the AI layer from becoming an unauditable model inside a build whose whole
claim is that nothing is fitted.

A real test: feed a canned response containing a pricing field, assert the returned structure
contains no numeric pricing field, and assert the discard was logged.
