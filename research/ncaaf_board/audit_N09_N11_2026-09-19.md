Independent verification from the bridge: artifacts, not the report.

the AI layer never executed, and the grader permanently sealed three unplayed games.**

## 1. What landed correctly

"Prediction 3: HELD" with t=1.25 under the probe's bins, the withdrawal block is present, and
the original claim is preserved as quoted history per the Kalshi convention. The script

## 2. DEFECT — the grader sealed three unplayed games, and the CLV log is poisoned

Current time at audit: **2026-09-19T00:41Z**. The three tickets:

| ticket | kickoff | status at grading | `graded` |
|---|---|---|---|
| Georgia @ Arkansas | 2026-09-19T16:00Z | **~15h in the future** | `True` |
| Colorado @ Northwestern | 2026-09-19T23:30Z | **~23h in the future** | `True` |
| Nebraska @ Michigan State | 2026-09-26T21:00Z | **~7 days in the future** | `True` |

`_load_closing_prices` correctly filters `snapshot_dt < commence_dt`. But for a game that has
not kicked off, **every** snapshot satisfies that predicate, so "closing price" resolves to the
most recent snapshot — the current line, which is the line the ticket was taken at.

Result: **12 of 12 legs carry `clv` of exactly 0.0.** Every leg's `close_price` equals its
`price`.

`grade_ncaaf_tickets.py:72` is `if ticket.get("graded"): continue`. UPDATE-ONLY means these
three tickets can never be re-graded. The CLV log — the entire measurement justification for
this build, the "free side-effect" that made an entertainment board worth instrumenting — is
corrupted on its first three entries and unrecoverable through the normal code path.

**Missing guard, one line:** skip any ticket whose `commence_time` is in the future. Grading is
only defined after kickoff.

**Recoverable right now, cheaply.** The games have not been played, so the decision prices are
intact. Setting `graded` back to `False` and clearing each leg's `close_price`/`clv` restores
all three tickets to gradeable. This must happen before anyone reads those rows as data.

## 3. DEFECT — the null control passed for the wrong reason

N11 reports the CLV null control as "3 then 0 (PASS)". The second pass changed zero rows
because the first pass had marked everything graded. The control was meant to demonstrate that
UPDATE-ONLY protects already-graded rows; what it actually recorded is that three rows were
sealed prematurely. A control that passes vacuously is worse than one that fails, because it
is reported as evidence.

**The tell was in the data.** Twelve legs with CLV of exactly 0.000 is not a plausible
measurement. If every CLV is exactly zero, the closing price is the decision price. Any future
grader run should assert that not all CLVs are identically zero and halt if they are.

## 4. DEFECT — the AI layer never ran, and the failure was reported as a pass

Every one of the three AI calls returned:

```
AI error: Error code: 404 - {'type': 'error', 'error':
{'type': 'not_found_error', 'message': 'model: claude-s...
```

`build_ncaaf_tickets.py:76` requests `model="claude-sonnet-4-20250514"`, which the API does not
recognise. The exception string was written into the `ai_rationale` field and the run
continued. `ai_flags` is `[]` on all three tickets.

N11 reports: *"AI guard: 0 discards (never triggered — untested)."* That is literally true and
substantively false. There were no AI responses to discard anything from, because there were no
AI responses. **Layer 3 was absent from the end-to-end run**, and the summary reads as though
it participated.

The design defect is broader than the model id: an API error was swallowed into an output field
rather than failing the item. A layer that cannot run should halt, not write its stack trace
into the deliverable and report success.

## 5. DEFECT — layer 2 covered 30 of 146 board teams

The news file holds 600 article rows across **30 distinct teams**. The board carries **146
distinct teams**. So news reached 21% of the board.

Root cause, `pull_ncaaf_news.py:119-124`: `board_teams` is derived from **the latest tape
snapshot**, while `build_ncaaf_board.py` builds the board from the full eligible tape. The two
layers disagree about which games are on the board.

N11's "30 teams with news (0 zero-article)" is true of the 30 queried and silent about the 116
never queried. The order asked for a count of teams returning zero articles specifically so a
silent hole in layer 2 would surface; the hole was upstream of the count.

## 6. What should happen

1. Un-seal the three tickets before they are read as data.
2. Add the future-kickoff guard and the all-CLV-identically-zero assertion.
3. Fix the model id; make an API failure in the AI layer halt the item rather than write itself
   into `ai_rationale`. Test the no-pricing-number guard with a canned response containing a
   number — a guard that has never been exercised is untested regardless of how many clean runs
   pass through it.
4. Make `pull_ncaaf_news.py` read its team list from the board artifact, not the latest
   snapshot, so layers 1 and 2 cover the same games by construction.
