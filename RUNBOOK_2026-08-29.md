## 1. REVOKE THE GITHUB TOKEN — do this first

A GitHub Personal Access Token is embedded in plaintext in the `origin` remote URL:

    git remote -v      # prints https://jwallace115:ghp_...@github.com/...

That token grants write access to the account. It is stored unencrypted in
`.git/config`, is printed by any `git remote -v`, and appears in the 2026-08-28/29
Claude conversation history.

    # 1. Revoke at github.com/settings/tokens  (find the token, Delete)
    # 2. Strip it from the remote:
    cd ~/mlb-model
    git remote set-url origin https://github.com/jwallace115/mlb-model.git
    git remote -v                      # confirm: no credentials in the URL
    # 3. Re-authenticate with a credential helper or SSH instead:
    gh auth login                      # simplest
    # or: git remote set-url origin git@github.com:jwallace115/mlb-model.git

**Check whether any cron/automation pushes using the embedded credential** — the
`auto: NBA pipeline run` and `auto: Statcast daily refresh` commits suggest something

the correct outcome; fix the auth, do not restore the token.

### Bug found and fixed during setup — read this

`multi_book_open_capture.py` called `load_dotenv(ROOT / ".env")`. python-dotenv
defaults to **`override=False`**, so an `ODDS_API_KEY` already exported in the shell
silently beat the `.env` value. A stale free-tier key was in the environment
(fp `46b88790`) while the paid key sat unused in `.env` (fp `ac6e89a0`). The dry run
looked completely healthy and reported `remaining: 497` — the free key's quota.

Fixed two ways:
- `load_dotenv(ROOT / ".env", override=True)` — `.env` is now authoritative
- every run logs `key fingerprint <sha256[:8]>` at startup, so a wrong key announces itself

The earlier $59 recommendation came from the cross-AI review and was endorsed
**without this calculation being done**. Recomputed from the actual config it is
oversized. The cross-venue test is inherently **forward-only** — Kalshi order-book
history cannot be purchased at any price, so there is nothing to backfill and the
10x historical multiplier never applies. It is a monthly subscription, not a
commitment; upgrade mid-month if a cap is actually hit.
